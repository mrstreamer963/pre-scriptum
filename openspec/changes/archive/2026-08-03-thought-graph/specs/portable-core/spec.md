## Purpose

Обеспечивает переносимость домена: core-модуль содержит чистую бизнес-логику (карточки, связи, граф, семантика) и общается с окружением только через API-контракт, что позволяет позже вынести его на Node.js-сервер без переписывания домена.

## ADDED Requirements

### Requirement: Чистый домен без зависимостей от окружения
Core SHALL содержать бизнес-логику (карточки, связи, плекс, семантический поиск) без прямых зависимостей от конкретного окружения (IndexedDB, файловая система, HTTP, конкретная модель эмбеддингов). Взаимодействие с окружением SHALL происходить только через определённые порты (интерфейсы).

#### Scenario: Core не зависит от хранилища
- **WHEN** core выполняет операции с карточками и связями
- **THEN** он использует абстрактный порт хранилища, а не конкретную реализацию

#### Scenario: Core не зависит от модели эмбеддингов
- **WHEN** core запрашивает генерацию эмбеддинга
- **THEN** он использует абстрактный порт эмбеддингов, а не конкретную модель

### Requirement: API-контракт core
Core SHALL предоставлять стабильный API-контракт для операций: создание/редактирование/удаление карточек, создание/удаление связей, получение плекса, семантический поиск, предложение связей.

#### Scenario: Операции через контракт
- **WHEN** вызывающий код (UI или сервер) выполняет операцию через API-контракт
- **THEN** core выполняет операцию и возвращает результат, не раскрывая внутренние детали

### Requirement: Переносимость на Node.js
Core SHALL быть спроектирован так, чтобы его можно было запустить на Node.js-сервере с другими адаптерами (файлы + SQLite, onnxruntime-node, HTTP API) без изменения домена.

#### Scenario: Замена адаптеров
- **WHEN** core запускается с Node-адаптерами вместо браузерных
- **THEN** домен работает без изменений, используя новые адаптеры через те же порты
